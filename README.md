# Учебный стенд управления учётными записями

Keycloak хранит пользователей и группы в PostgreSQL. NGINX принимает HTTPS на порту 8443. OAuth2 Proxy использует OpenID Connect и открывает портал участникам /portal-users. В Compose запускаются пять контейнеров. В Swarm работают две реплики Keycloak и четыре одиночных сервиса.

## Подготовка

Нужны Docker Desktop в режиме Linux-контейнеров или Linux с Docker Engine и Compose, Python 3, OpenSSL и Node.js. В PowerShell при наличии Git for Windows можно задать путь к OpenSSL:

    $env:IAM_OPENSSL = 'C:\Program Files\Git\usr\bin\openssl.exe'

При распаковке используйте новый рабочий каталог. Скрипт создаёт .secrets для конкретной установки. Сохраните этот каталог при повторном запуске с существующей БД. Для Compose порт 8443 должен быть свободен. Локальный Swarm использует этот же порт, поэтому запускайте режимы по очереди.

## Локальный режим Compose

    python scripts/prepare.py
    docker compose config --quiet
    docker compose up -d --build
    npm install --no-save playwright@1.61.1
    npx playwright install chromium
    node scripts/smoke.cjs --capture

Сценарий проверяет HTTPS и жизненный цикл временной записи в браузере, затем удаляет эту запись. Скриншоты записываются в evidence. При наличии установленного Chrome можно задать BROWSER_PATH и пропустить скачивание Chromium.

Чтобы перейти в кластерный режим, освободите порт:

    docker compose down

Именованный том PostgreSQL сохраняется.

## Двухузловой режим в Docker Desktop

    python scripts/local_lab.py
    docker exec iam-course-manager docker node ls
    docker exec iam-course-manager docker stack ps --filter desired-state=running iam
    node scripts/smoke.cjs --capture

Сценарий запускает два привилегированных контейнера Docker-in-Docker и размещает внутри них учебный Swarm. Применяйте этот режим только в собственной лабораторной среде. Из внешнего хоста порт опубликован на 127.0.0.1. При повторном запуске используются два контейнера с меткой стенда. Сборка получает локальный тег на основе идентификатора образа. Развёртывание использует образы, предварительно загруженные в оба внутренних движка.

Чтобы остановить локальный Swarm и сохранить его состояние:

    docker stop iam-course-worker iam-course-manager

## Демонстрация в браузере

Автотест сам настраивает разрешение имён и проверку сертификата. Для ручного входа сопоставьте 127.0.0.1 с iam.test и portal.test в локальном DNS или файле hosts. Добавьте .secrets/ca_cert в доверенные корневые сертификаты отдельной лабораторной среды. Удалите лабораторный корневой сертификат из доверия после демонстрации.

Откройте https://iam.test:8443/admin/. Пользователь администратора — lab-admin, пароль находится в .secrets/admin_password. В области iam создайте тестового пользователя с именем, фамилией и адресом в домене lab.example. Отметьте адрес как подтверждённый. Задайте пароль и добавьте /portal-users. В отдельном приватном окне откройте https://portal.test:8443/. Отключите пользователя в Keycloak, завершите его сеансы и повторите вход в новом контексте. Ожидается отказ.

## Репозиторий и GitHub Actions

Файл .github/workflows/iam.yml проверяет сборку в Compose, передаёт проверенный образ на публикацию в GHCR и развёртывает его в двухузловом Swarm на исполнителе GitHub. Задание развёртывания получает образ по дайджесту и повторяет браузерные тесты. Тестовый кластер живёт до окончания задания. Вывод команд и скриншоты сохраняются в артефакт swarm-evidence.

После публикации в отдельном долговременном Swarm подготовьте секреты на менеджере, добавьте метку iam_db=true узлу с постоянным томом и передайте IAM_IMAGE с дайджестом в scripts/deploy.py. При необходимости задайте IAM_TARGET с адресом входного узла. Доступ к приватному пакету GHCR должен быть настроен на менеджере. Начальная область импортируется при первом запуске. Изменения существующей области вносятся через Keycloak.
## Файлы

- Dockerfile и config/keycloak-entry.sh — сборка Keycloak и чтение секретов.
- docker-compose.yaml и stack.yaml — локальное и кластерное описание.
- config — шаблон области, два прокси и демонстрационный портал.
- scripts/prepare.py — подготовка секретов и сертификатов.
- scripts/deploy.py — запуск, масштабирование и проверка стека.
- scripts/local_lab.py — два Docker Engine на одном компьютере.
- scripts/smoke.cjs — браузерные сценарии.
- evidence — результаты контрольных прогонов и скриншоты, если приложены.
